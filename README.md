# KMSAN — نقطة بيع ومخزون لمحل ألبسة

تطبيق Flutter واحد يعمل على **ويندوز** (حاسوب المحل والطباعة) و**أندرويد**
(هاتف البائع)، عربي وفرنسي، RTL، يعمل دون إنترنت ويُزامن عند عودته.
معه متجر إلكتروني منفصل في `storefront/` يقرأ المنتجات المنشورة.

---

## ⚠️ قبل أول تشغيل

| القيمة | المكان | الحالة |
|---|---|---|
| `storeDisplayName` | `lib/core/constants/app_constants.dart` | ✅ «الأصيل» — مكتوب **مرة واحدة** في المشروع كله |
| `cloudinaryCloudName` + `cloudinaryUploadPreset` | نفس الملف | ✅ `vw1jzuvi` / `9msane` — مُختبَران برفع فعلي |
| الشعار | `assets/images/logo.png` | ✅ شعار «الأصيل» — لتغييره: بدّل الملف ثم `dart run tool/generate_icons.dart` و`tool/make_logo_asset.dart`، أو غيّره من داخل التطبيق (الإعدادات ← المظهر) بلا إعادة بناء |
| `VITE_STORE_ID` | `storefront/.env.local` | ⬜ بدونه يعرض المتجر «غير مهيّأ» بدل المنتجات |
| نشر `firestore.rules` | مشروع Firebase الحيّ | ⬜ بدونه لا تصل هوية المتجر إلى الموقع (403) |
| `android/key.properties` | من `key.properties.example` | ⬜ بدونه يُوقَّع الـ APK بمفتاح debug |

الرفع غير الموقّع مصمَّم أصلاً للعمل من تطبيق العميل، فلا يوجد سرّ في الكود.
للتحقّق من أي preset دون رفع صورة تبقى في الحساب:

```bash
curl -s -X POST "https://api.cloudinary.com/v1_1/CLOUD/image/upload" -F "upload_preset=PRESET"
```

`Missing required parameter - file` = الـ preset موجود ومقبول.
`Upload preset not found` = الاسم خطأ أو الـ preset ليس Unsigned.

## التشغيل

```bash
flutter pub get
flutter run -d windows
```

أول حساب: أنشئه من لوحة Firebase (Authentication → Users → Add user).
عند أول دخول يصير صاحب المحل تلقائياً ويُنشأ متجره (`storeId = uid`).

## البناء والتوزيع

```bash
flutter build windows --release
```

```bash
flutter build apk --release --split-per-abi
```

**توقيع الإصدار**: إن وُجد `android/key.properties` وُقّع التطبيق بمفتاحك،
وإلا عاد إلى مفتاح debug (انظر `android/key.properties.example`). المفتاح
الحقيقي مهمّ: بمفتاح debug يستطيع أي شخص توليد «تحديث» يقبله أندرويد على
أنه التطبيق نفسه، وأي إعادة بناء من حاسوب آخر تُنتج توقيعاً مختلفاً فيضطر
صاحب المحل لحذف التطبيق وفقدان إعداداته. إنشاء المفتاح:

```bash
keytool -genkey -v -keystore kmsan-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias kmsan
```

⚠️ احتفظ بنسخة من الملف وكلمة سرّه في مكان آمن — فقدانه يعني أن **كل**
تحديث لاحق سيُرفض على الأجهزة المثبَّت عليها التطبيق.

`--split-per-abi` مقصود: النسخة الموحّدة **90 ميغا** لأنها تحمل شيفرة
المعالجات الثلاثة معاً، بينما `app-arm64-v8a-release.apk` وحده **38 ميغا**
— وهو ما يناسب هواتف اليوم كلّها تقريباً، والتوزيع يتمّ يدوياً عبر واتساب
أو USB (أرقام مقاسة من آخر بناء).
(ابنِ الموحّدة بلا العلَم إن احتجت ملفاً واحداً يعمل على أي هاتف.)

مثبّت ويندوز — افتح `windows_setup.iss` بـ Inno Setup ثم Compile
(يحزم مجلد Release كاملاً؛ الـ exe وحده لا يعمل لأنه يحتاج الـ DLLات
ومجلد `data` الذي فيه خطوط Amiri للطباعة).

نشر قواعد الأمان:

```bash
firebase deploy --only firestore:rules --project mesan-869c2
```

> ⚠️ راقب مخرجات الترجمة. تحذير `Invalid variable name: database` يعني أن
> دوال القواعد خرجت من كتلة `match` — عندها `exists()` لا يعمل و**يفقد كل
> العمال صلاحياتهم بصمت**. آخر نسخة هنا تُترجم بلا هذا التحذير.

بعد النشر، تحقّق من عدم التسريب بطلب غير مصادَق (لا حاجة لأي أداة):

```bash
curl -s -o /dev/null -w "%{http_code}
" "https://firestore.googleapis.com/v1/projects/mesan-869c2/databases/(default)/documents/stores/anyStore/products"
```

النتيجة المطلوبة **403**. أما المسار العام
`publicCatalog/{storeId}/products` فيجب أن يرجع **200** وبلا أي
`purchasePrice` في جسم الرد.

> ملاحظة: مستند هوية المتجر `publicCatalog/{storeId}/meta/storefront`
> يرجع 403 ما دامت القواعد لم تُنشر بعد إضافته — وحينها يعرض الموقع الاسم
> الافتراضي بلا روابط تواصل. إن رأيت ذلك فالسبب هو النشر لا الكود.

## البنية

```
lib/
  core/{constants, router, theme}
  features/<feature>/{data, domain, presentation/{providers,screens,widgets}}
  shared/{services, utils, widgets}
```

الحالة: **Riverpod 3** (`Notifier` / `StreamProvider` / `Provider`). التوجيه:
`go_router`. لا BLoC.

### قاعدة متكرّرة في كل المستودعات

لا `where` مع `orderBy` على حقلين مختلفين. كل تركيب منهما يطلب فهرساً
مركّباً، وأول ما يحدث ذلك تتوقّف الشاشة عند العميل برسالة إنجليزية غامضة.
**الترتيب والفلترة محلياً** — حجم بيانات محل واحد يسمح بذلك.

## القرارات التي دفعت ثمنها مرة، فلا تُعِدها

### الثيم فاتح إجبارياً
`themeMode: light` و`darkTheme = lightTheme` معاً. مع `ThemeMode.system` كان
الهاتف يفتح بالوضع الليلي فتصير النصوص بيضاء على بطاقات بيضاء. **لا لون نص
أبيض في `labelStyle` أو `hintStyle` أبداً.**

### تخطيط نقطة البيع بالعرض لا بالارتفاع
`MediaQuery.sizeOf(context).width` فقط. فتح لوحة المفاتيح يُنقص الارتفاع؛ لو
بُني القرار عليه لتبدّلت شجرة الـ widgets عند كل كتابة، وارتجفت الشاشة،
واختفى زرّ الدفع.

### الباركود 8 أرقام لا 13
عرض الوحدة (أرفع خط) يجب أن يكون **مضاعفاً صحيحاً لنقطة الطابعة**، وإلا
قرّبت الطابعة بعض الخطوط لـ2 وبعضها لـ3 فتفاوتت السماكات ولم يُقرأ الرمز.
على ملصق 40مم بدقّة 203dpi:

| الطول | الوحدات | نقاط/وحدة | النتيجة |
|---|---|---|---|
| 8 أرقام | 79 | **3** | يُقرأ من بعيد |
| 12 رقماً | 101 | 2 | على الحافة |
| 13 رقماً | 123 | 2 | لا يُقرأ |

13 رقماً هو الأسوأ: الطول الفردي يُجبر Code128 على تبديل مجموعة المحارف
فيضيف 22 وحدة. والرمز يُرسم بعرضه المحسوب **ولا يُمدّ ليملأ الملصق**، مع
منطقة صامتة ≥10 وحدات على كل جانب (شرط المعيار).
الأرقام أعلاه مثبَّتة في `test/barcode_metrics_test.dart`.

### الملصقات الفارغة — DEVMODE من الدرايفر نفسه
الطابعة تتقدّم بمقدار **الفورم المضبوط في درايفرها** لا بمقدار الصفحة
المرسلة، ومكتبة `printing` تبني DEVMODE مصفَّراً بلا بيانات الدرايفر الخاصة
فيتجاهله. الحلّ في `windows_printer_ffi.dart`: نأخذ DEVMODE الحقيقي عبر
`DocumentProperties(DM_OUT_BUFFER)`، نضبط `dmPaperSize = DMPAPER_USER (256)`
— **ليس 0**، بعض الدرايفرات ترفض الصفر — ثم نمرّره على الدرايفر ليصحّحه،
ونحفظه بـ `SetPrinter` **مستوى 9** (افتراضي المستخدم، بلا صلاحيات مدير)،
ثم **نقيس** بـ `GetDeviceCaps` أن صفحة الجهاز صارت = الملصق (±0.6مم).
نجاح النداء وحده لا يُصدَّق.

وإذا أرجعت الطباعة المباشرة `false` **لا نُعيد الإرسال عبر نافذة الطباعة**:
قد تكون الورقة خرجت فعلاً فتخرج نسخة ثانية.

### الوصل بطول ديناميكي
يُبنى بارتفاع `double.infinity`؛ مكتبة `pdf` تكتب الارتفاع المحسوب في
`page.pageFormat` بعد `save()`، فنقرأه ونرسله كمقاس ورق. وصل بسلعة واحدة
**82مم** مقاساً لا ورقة كاملة (`test/printing_layout_test.dart`).

### خطوط الطباعة
الخطوط الافتراضية في مكتبة `pdf` **لا ترسم العربية إطلاقاً** — تخرج الوصولات
فراغات بلا أي خطأ. كل صفحة تُبنى بـ `ThemeData.withFont` مع Amiri المضمَّن
في `assets/fonts` و`textDirection: rtl`.

### سحب الأرباح ليس مصروفاً
نوع مستقلّ `profitWithdrawal`. لو حُسب مصروفاً لظهرت «الفائدة بعد المصاريف»
أقلّ مما هي كل يوم ولبدا المحل خاسراً وهو رابح. الحركات القديمة تُعرف
بملاحظتها («إغلاق الصندوق» / «سحب أرباح») للتوافق الرجعي
(`test/reports_math_test.dart`).

### شراء البضاعة ليس مصروفاً أيضاً
نوع `purchase` مستقلّ. ثمن البضاعة يدخل الحساب **مرّة واحدة عند البيع**
كتكلفة مبيعات؛ لو عُدّ مصروفاً يوم الشراء لحُسب مرّتين ولظهر شهر التموين
كارثة وشهر البيع معجزة. المشتريات تظهر في التقرير في سطرها الخاص
(`test/reports_math_test.dart`).

### سعر الشراء يتغيّر مع كل وصولية مورّد
شاشة «مشتريات جديدة» تحدّث الكمية وسعر الشراء ورصيد المورّد وحركة الصندوق
في **دفعة واحدة**. تُعرض التكلفة السابقة بجانب الجديدة وقت الإدخال، وتُقترح
تعديل سعر البيع، لأن اكتشاف أن الهامش صار سالباً بعد أسبوع من البيع متأخّر.

### إغلاق الصندوق يبدأ يوماً محاسبياً فوراً
`lastDayClose` يصير بداية فترة «اليوم»، فتعود كل الأرقام صفراً أمام صاحب
المحل بدل انتظار منتصف الليل.

### وعاء الزكاة
= المخزون (بسعر البيع) + نقد الصندوق + كريديات الزبائن، × 2.5٪
(`test/capital_math_test.dart`). كان هناك «مخزون خاص» منفصل وحُذف بطلب
صاحب المحل؛ إن رأيت أثراً له في بيانات قديمة فهو مهمَل ولا يدخل أي حساب.

### إنشاء حساب عامل
تطبيق Firebase **ثانوي باسم فريد لكل محاولة** (اسم ثابت يورّث جلسات قديمة)،
لأن إنشاء مستخدم يسجّل دخوله تلقائياً وكان يُخرج الأدمن من حسابه. ولو فشل
حفظ المستندات نحذف حساب Auth اليتيم وإلا بقي البريد محجوزاً للأبد.

### اختيار وجهة السحب قائمة صريحة لا Autocomplete
نسخة Autocomplete كانت تُنشئ مستمعاً في كل إعادة بناء يمسح الاختيار، فتُحفظ
السحوبات بلا حساب ولا يظهر لها أثر في أي تقرير.

### 🚫 تسريب البيانات
`publicCatalog` يقرأه أي زائر على الإنترنت. هناك **مرآتان** عامّتان، ولكلٍّ
قائمة بيضاء صريحة واختبار يسقط عمداً عند إضافة أي حقل جديد
(`test/model_rules_test.dart`):

| المرآة | المسموح | الممنوع |
|---|---|---|
| `Product.toPublicMap()` | الاسم، الوصف، سعر البيع، النوع، الصور، المقاسات، الألوان، التوفّر | `purchasePrice`، `supplier`، `barcode`، الكمية |
| `StoreSettings.toStorefrontMap()` | اسم المحل، الجملة التعريفية، الهاتف، روابط التواصل | `pinHash`، نسبة خصم VIP، أي إعداد داخلي |

قائمة الحقول في `toStorefrontMap` **نسخة طبق الأصل** من `hasOnly([...])` في
`firestore.rules`. لو اختلفتا رفضت Firestore الكتابة كاملةً وبقي الموقع على
بيانات قديمة **بصمت** — ولهذا الاختبار يقارنهما.

## ما يُضبط من الإعدادات (لا من الكود)

صاحب المحل يغيّر هذه كلّها من داخل التطبيق بلا مبرمج وبلا إعادة بناء:

| الإعداد | أين يظهر أثره |
|---|---|
| **الرقم السرّي** | يقفل كل الأقسام عدا نقطة البيع — القفل في `app_router.dart` نفسه لا في الشاشات |
| **أنواع المنتجات** | بطاقة المنتج الجديد + شريط الفرز في نقطة البيع + تصنيفات المتجر |
| **المقاسات** | تُكتب يدوياً وتظهر كخيارات في بطاقة المنتج |
| **الألوان** | تُختار من دائرة ألوان HSV، فيُحفظ الاسم العربي وقيمة ARGB الدقيقة |
| **شعار المحل** | يُختار صورةً من الإعدادات ← المظهر، فيظهر علامةً مائية وفي القائمة وشاشة الدخول وعلى الوصل. **مشترك بين الأجهزة** |
| **محتوى الوصل** | اسم المحل (قابل للكتابة، محلّي لكل جهاز) ومحاذاته، أسطر ترويسة وتذييل حرّة، لوغو بعرضه وموضعه، رموز QR لفيسبوك وإنستغرام |
| **هوية المتجر الإلكتروني** | الاسم والجملة التعريفية والهاتف وروابط التواصل وعنوان الموقع — تُنشر فوراً إلى الموقع، والعنوان يفتحه زرّ في شاشة الطلبات |
| **الثيم واللغة** | 5 لوحات ألوان + عربية/فرنسية، محليّة لكل جهاز |

> اسم المحل موجود في **موضعين مقصودين**: اسم الوصل (محلّي لكل جهاز، مع
> إعدادات الطباعة) واسم المتجر الإلكتروني (مشترك، يُنشر للموقع). ليسا
> تكراراً: قد يطبع فرعان وصلين باسمين مختلفين والموقع واحد.

### الشعار والأيقونات

مصدر واحد: `tool/assets/logo_source.png` — **خارج `assets/` عمداً**، لأن كل
ما في `assets/` يُحزَم داخل التطبيق، وصورة المصدر (1.1 م.ب) لا يقرأها
التطبيق أبداً. بعد تبديلها:

```bash
dart run tool/generate_icons.dart
```

يولّد أيقونات أندرويد الخمس، وملف `app_icon.ico` بسبعة مقاسات (ويندوز
يحتاجها في الملف نفسه، وإلا كبّر الأقرب فبدت الأيقونة مهترئة في شريط
المهام)، و`favicon.png` للمتجر.

```bash
dart run tool/make_logo_asset.dart
```

يولّد `assets/images/logo_mark.png`: الشعار بخلفية **شفّافة**. الشفافية
ليست تجميلاً — التطبيق يلوّن الشعار (علامة مائية بلون النصّ، شعار بلون
الهوية)، و`srcIn` تصبغ كل بكسل معتم، فلو بقيت الخلفية بيضاء لصار الشعار
مربّعاً مصمتاً. السكربت يطبع نسبة البكسلات غير الشفّافة: قربها من 100٪
يعني أن الخلفية لم تُزَل.

> لتغيير الشعار **بلا إعادة بناء** أصلاً: الإعدادات ← المظهر ← «اختيار
> شعار». يُصغَّر إلى 512 بكسل ويُحفظ في إعدادات المتجر المشتركة، فيتغيّر
> على هاتف العامل أيضاً.

### العربية والفرنسية

المفتاح هو **النصّ العربي نفسه**، لا رمز مثل `pos.title`:

```dart
Text(tr('نقطة البيع'))            // ← Point de vente
Text(trf('{0} قطعة', [count]))    // ← 5 pièce(s)
```

نصّ بلا ترجمة يظهر بالعربية لا فارغاً ولا كرمز غامض — وهذا مضمون باختبار.
لإضافة نصّ جديد: اكتبه داخل `tr()` واعمل، ثم أضف سطره إلى
`lib/core/i18n/strings_fr.dart` متى شئت.

> في `strings_fr.dart` تُستعمل الفاصلة العليا الطباعية `’` لا `'`، لأن
> `'` تُنهي نصّ Dart فتكسر الملف كلّه (`l’article` لا `l'article`).

## المتجر الإلكتروني (`storefront/`)

موقع React + Vite منفصل، يقرأ `publicCatalog` بلا مصادقة ويكتب الطلبات في
`publicOrders`.

```bash
cd storefront
npm install
cp .env.example .env.local     # ثم ضع VITE_STORE_ID = uid صاحب المحل
npm run dev
```

- اسم المحل وجملته وهاتفه وروابط فيسبوك/إنستغرام تأتي من **إعدادات
  التطبيق** عبر `publicCatalog/{storeId}/meta/storefront`، فيغيّرها صاحب
  المحل من هاتفه وتظهر في الموقع فوراً بلا إعادة نشر.
- أزرار التواصل تظهر فقط إن ضُبطت روابطها، ورموز QR مخفيّة على الهاتف
  عمداً (لا أحد يمسح رمزاً معروضاً على الهاتف الذي يمسك به).
- رقم الطلب يُحجز بمعاملة ذرّية، والقواعد تسمح بزيادته **بواحد فقط**، فلا
  يستطيع زائر القفز به أو تخريبه.

## اختصارات لوحة المفاتيح (الحاسوب)

| المفتاح | الفعل |
|---|---|
| `Enter` | بيع نقدي فوري بلا طباعة وبلا أي نافذة |
| `Space` | نفس الشيء مع طباعة الوصل |
| `Escape` | تفريغ حقل البحث |

تعمل **أينما كان التركيز وحتى دون لمس الفأرة**: يلتقطها `Focus` جدّ يلفّ
الشاشة (`canRequestFocus: false`, `skipTraversal: true`). الاستثناء الوحيد:
إن كان في حقل البحث نصّ فـ`Enter` للبحث (القارئ السلكي).

## الطباعة عن بُعد

الهاتف يضع أمراً في `stores/{id}/print_jobs` **بلا PDF** — الحاسوب يعيد بناء
المستند من قاعدة البيانات بإعداداته ومعايرته هو. العامل يحجز الأمر بمعاملة
ذرّية (ضدّ الطباعة المزدوجة)، ويقرأ المستند بإعادة محاولة (6×700مللي) لأن
البيع متفائل وقد يسبق أمرُ الطباعة كتابةَ الفاتورة.

---

## الاختبارات

```bash
flutter test
```

97 اختباراً تغطّي: حساب وحدات Code128 والمنطقة الصامتة ومقروئية 8 مقابل 13
رقماً، ارتفاع الوصل الديناميكي، ارتفاع صفحة التيكت = الخطوة، تصنيف سحب
الأرباح والمشتريات (النوع والملاحظات القديمة)، وعاء الزكاة، منع تسريب حقول
المرآتين العامّتين، محلّل ملفات الاستيراد (xlsx/csv)، وسلامة قاموس الفرنسية
(السقوط الآمن وتطابق القيم المتغيّرة `{0}`)، وهوية المحل على الوصل
(الاسم المخصَّص يصل الورق فعلاً، وشعار تالف لا يُفشل الطباعة).

## ملاحظات

- **الويب ليس هدفاً**: نظام الطباعة يستعمل `dart:ffi` الذي لا يُترجم للويب.
  مجلد `web/` باقٍ لأن تهيئة Firebase للويب هي نفسها المستعملة على ويندوز.
- `applicationId` هو **`KMSAN.APP`** حرفياً بالأحرف الكبيرة، لأن
  `google-services.json` يطابقه هكذا. الأحرف الكبيرة في اسم الحزمة غير
  تقليدية وقد تمنع النشر على Google Play لاحقاً؛ التطبيق يُوزَّع APK مباشرة
  فلا مشكلة الآن.
- الصور تُرفع إلى Cloudinary لا Firebase Storage (الأخير يتطلب بطاقة بنكية).
  الحذف يتطلّب مفتاح إدارة لا يجوز وضعه في تطبيق العميل، فالصور اليتيمة
  تُسجَّل في `orphanImages` وتُنظَّف يدوياً من لوحة Cloudinary.
